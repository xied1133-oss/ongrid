# PRD-003：非 Kubernetes 设备集群管理

## 元信息

- 状态：已完成
- 作者：Codex
- 日期：2026-07-31
- 关联 Epic：不适用
- 关联 ADR：不适用（复用现有 Topology 节点与关系模型）
- 关联 HLD：不适用（不新增服务或领域边界）

## 背景

批量安装已经支持把非 Kubernetes 设备自动归属到拓扑集群，设备列表也能展示所属集群，但平台缺少面向这类集群的独立管理入口。运维人员目前只能在通用拓扑页查看关系，无法快速回答“有哪些设备集群、每个集群有多少在线成员、哪些安装批次仍然有效”，也不能在同一处维护成员关系。

## 目标

- 让运维人员在一个独立入口查看全部非 Kubernetes 设备集群及成员健康概览。
- 在集群详情中完成成员添加、移除、集群重命名和安全删除。
- 在集群上下文内创建、查看和删除批量安装配置。
- 在集群上下文内安全批量升级成员 Edge；任务离开页面后继续执行，并可追溯逐设备结果。
- Kubernetes 托管集群和设备继续由 Kubernetes 专用页面管理，不混入本功能。

## 功能需求

### 核心功能

- 基础设施导航新增“集群”入口，列表只展示 `type=cluster` 且 `props.source != kubernetes` 的拓扑节点。
- 列表展示集群名称、成员总数、在线/离线分布、有效安装批次数和最近更新时间，并支持名称搜索。
- 集群详情展示成员设备名称、主机名、IP、角色、在线状态、最后心跳和关系来源。
- 集群详情展示成员 Edge 当前版本，并标记与 Manager 版本不一致的设备。
- 管理员可将尚未归属其他非 Kubernetes 集群的普通设备加入当前集群，也可仅删除成员关系而不删除设备。
- 管理员可重命名集群；只有不存在任何拓扑关系且没有有效安装配置的空集群可以删除。
- 集群列表操作栏与详情页页头均提供直接删除入口，不再单独展示“集群生命周期”说明卡片；存在依赖时入口禁用并提示阻塞原因。
- 管理员可在当前集群内生成批量安装命令；生成的配置固定关联当前集群。
- 集群详情展示关联安装批次的状态、使用量、有效期，并支持直接删除任意状态的批次。
- 管理员可在升级前查看可升级、离线、未关联 Edge、系统或架构不支持的成员数量；默认只对在线且关联 Host Edge 的 Linux amd64 / arm64 设备发起升级。
- 升级前读取 Manager 当前版本的 amd64 / arm64 制品状态；缺失或校验文件异常的架构不发送升级请求。
- 已经处于目标版本的设备默认跳过；管理员可显式选择“强制重新安装同版本设备”用于修复损坏安装。
- 管理员确认预检后只创建一条持久化升级任务；Manager 默认每批最多处理 10 台设备，每批内部最多 8 台并发下发不同架构的软件包，浏览器关闭或离开页面不会中断任务。
- 当前批次的全部设备都进入成功、失败或超时终态后，Manager 才开始下一批；单台失败不会阻塞后续批次。
- 集群详情展示最近升级任务及成功、失败、跳过、处理中数量和当前/总批次；任务详情保留逐设备批次、架构、原版本、目标版本、尝试次数、状态和失败原因。
- Manager 等待 Edge 产生新的注册时间并上报目标版本，两项均满足后才将该设备标记为成功；失败或确认超时的设备可从原任务中定向重试。
- Manager 重启后自动恢复排队任务和中断在下发阶段的设备；已进入重新注册确认阶段的设备继续使用原截止时间确认，避免重复下发。

### 边界情况

- Kubernetes 托管设备不能被加入普通设备集群。
- 没有 `node_id` 的设备暂不可加入，等待设备拓扑镜像完成后再操作。
- 已属于其他普通集群的设备不能重复加入；当前集群内的重复操作保持幂等。
- 删除成员关系不删除设备、Edge 身份、凭证或观测数据。
- 删除安装批次会立即使其安装命令失效并清理领取记录，但不删除已经生成的 Edge 身份或设备。
- 离线、未关联 Edge、非 Linux 或架构未知的成员不进入升级请求，并在预检中明确列为跳过项。
- Edge 接受升级指令只会把设备明细推进到“等待重连”；后台协调器必须同时观察到新的 `last_registered_at` 和目标 `agent_version` 才视为完成。
- 90 秒内未观察到重新注册时标记为“确认超时”。任务完成后管理员可主动重试失败或超时设备；重试会刷新注册基线并重新按每批最多 10 台编排，避免把旧会话误判为本次成功。
- 不同架构必须使用各自的软件包；单条升级任务最多包含 500 台 Edge，并由 Manager 通过“批次上限 10 + 批内并发上限 8”控制流量。
- 集群不存在、类型不正确或属于 Kubernetes 时，详情页展示明确的不可用状态并返回列表入口。
- 活跃安装配置或其他拓扑依赖存在时，不提供删除集群操作。

## 非功能需求

- **性能**：后台协调器默认每批最多 10 台、批内最多并发下发 8 台，并批量读取当前批次待确认 Edge 状态；页面仅在存在运行中任务时每 5 秒刷新列表或当前详情。
- **安全**：所有写操作继续使用 Topology 与 Edge 现有管理员权限；安装令牌仍只显示一次。
- **升级安全**：继续复用 Edge 整包升级的 SHA-256 校验、原子替换和失败自动回滚能力；预检不会向离线或无法识别架构的设备发送指令。
- **兼容性**：新增删除 API；旧撤销接口仅为兼容已有客户端保留，设备页与集群页统一使用删除操作。
- **可靠性**：升级任务持久化批次大小、当前批次、总批次及逐设备批次/状态；Manager 重启先恢复原当前批次，未收敛前不会越过批次屏障，完成记录保留 90 天后由后台定期清理。
- **运维 / 回滚**：旧同步批量升级 API 继续保留兼容；回滚前端不会影响已在 Manager 后台执行的升级任务。

## API 变更

- `DELETE /api/v1/edge-enrollment-profiles/{id}`：删除安装批次及其领取记录，保留已创建的 Edge 和设备。
- `GET /api/v1/edge-bundles`：返回 Manager 当前版本的 amd64 / arm64 制品可用性、大小和校验摘要，不暴露本地文件路径或下载凭据。
- `POST /api/v1/edge-upgrade-jobs`：创建持久化后台升级任务，集群任务会验证所有目标设备仍属于指定集群。
- `GET /api/v1/edge-upgrade-jobs?cluster_node_id={id}`：分页查询集群升级记录。
- `GET /api/v1/edge-upgrade-jobs/{id}`：查询任务汇总和逐设备明细。
- `POST /api/v1/edge-upgrade-jobs/{id}/retry`：仅重置并重试失败或确认超时的设备。
- 保留 `POST /api/v1/edges/batch/upgrade-package` 供旧客户端兼容，新集群页面不再依赖浏览器持续调用该接口。

## 数据库变更

- `edges.last_registered_at`：记录最近一次完成 `register_edge` 的时间；心跳不更新该字段，用于确认升级后的新 Agent 会话。
- `edge_upgrade_jobs`：持久化目标版本、集群、创建人、任务状态、批次大小、当前/总批次、汇总计数和起止时间。
- `edge_upgrade_job_items`：持久化每台设备的批次、身份快照、架构、版本、尝试次数、状态、错误和重新注册观测值。
- 删除安装批次时在同一事务内清理 `edge_enrollment_profiles` 与关联的 `edge_enrollments` 记录。

## 依赖与阻塞

- 依赖 PRD-002 提供的批量安装配置和设备集群归属。
- 依赖现有设备到拓扑节点的 `node_id` 镜像。
- 依赖 Manager 的 Edge bundle 目录为目标版本同时提供 `linux-amd64` / `linux-arm64` 制品；原生部署需正确配置 `ONGRID_EDGE_BUNDLE_DIR`。
- 无阻塞项。

## 风险与假设

- 列表聚合使用现有通用查询接口；超大规模下后续可增加服务端聚合接口，本期不引入新的 API。
- 设备默认只归属一个非 Kubernetes 集群；通用拓扑仍允许表达其他类型关系。
- 删除只对完全无关系、无有效安装配置的集群开放；有效安装批次可先直接删除，使已分发但尚未使用的命令失效。
- 若 Manager 未打包某一架构、校验文件异常、公开下载地址未配置或 bundle 目录不可读，预检会阻止对应架构；其他制品正常的架构仍可升级。
- Edge 升级会产生短暂断连；新注册时间只证明新会话已经建立，必须再结合 Agent 自报版本判断成功或回滚。
