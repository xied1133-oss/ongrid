# PRD-002：非 Kubernetes Edge 批量安装

## 元信息

- 状态：开发完成，待环境验收
- 作者：Codex
- 日期：2026-07-31
- 关联 issue：用户直接需求
- 关联 Epic：不适用
- 关联 ADR：不适用（复用现有 Edge 身份与拓扑节点模型）
- 关联 HLD：不适用（不新增服务，仍在 Edge 与 Topology 现有边界内实现）

## 背景

非 Kubernetes 环境当前需要先创建一台 Edge，再逐台复制各自的 AccessKey 和 SecretKey 执行安装。大量物理机或虚拟机接入时操作重复，而且不能在安装阶段统一表达“这些设备属于同一安装批次”或“这些设备属于同一业务集群”。

直接让多台设备复用同一对 Edge 凭证不可行：每台设备会争用同一个 Edge 身份和隧道路由，既无法可靠区分设备，也扩大了密钥泄漏后的影响范围。

## 目标

- 管理员一次创建可复用的安装配置并获得一条通用安装命令。
- 每台主机使用安装令牌领取自己独立的 AccessKey 和 SecretKey，随后继续使用现有 Edge 注册、隧道和插件链路。
- 安装配置支持“仅批次”和“关联集群”两种模式；集群模式在设备首次注册时自动建立 `Device --member_of--> Cluster` 关系。
- 安装令牌具备过期时间、最大使用次数和主动撤销能力，且服务端不保存明文。

## 功能需求

### 核心功能

- 每个安装配置都有名称、归属模式、有效期、最大领取次数、已领取次数和状态。
- `batch_only` 模式只记录同一安装批次，不创建拓扑关系。
- `cluster` 模式必须绑定一个现有 `type=cluster` 拓扑节点；客户端领取时不能提交或覆盖集群 ID。
- 安装配置创建后不提供修改模式或集群的接口，避免一条已经分发的命令改变归属语义。
- 每台主机以稳定硬件指纹领取独立 Edge 凭证。同一配置、同一主机在首次注册完成前重试时复用 Edge 身份并轮换临时 Secret，不重复消耗名额。
- 首次 Edge 注册完成后写入设备 ID；集群模式幂等创建 `member_of` 关系。
- 设备列表分别以带颜色的 `K8s`、`Host` 标签标识 Kubernetes 与普通设备，Kubernetes 不再区分 Controller 与 Node；两类集群归属均使用 `集群 · 名称` 标签，便于直接确认设备归属。
- 管理员可查看安装配置列表和撤销仍在使用的配置；列表永不回显令牌。

### 边界情况

- 过期、撤销、达到使用上限或不存在的令牌均不能再领取新身份。
- 同一主机已完成注册后再次使用同一安装命令会被拒绝，防止覆盖在用凭证。
- 集群节点在领取前若已删除或不再是 `cluster` 类型，领取失败。
- 设备若已经由另一条 Edge 批量安装配置归属到其他集群，则拒绝产生第二个自动集群归属；人工关系和 Kubernetes 关系不在本功能内改写。
- 旧的逐台创建和 AccessKey/SecretKey 安装方式保持可用。

## 非功能需求

- **安全**：安装令牌使用至少 256 bit 随机熵，数据库只保存 SHA-256 摘要；SecretKey 继续仅保存 Argon2id 哈希。令牌和 SecretKey 不进入服务日志。
- **滥用控制**：领取接口限制请求体大小、并发数并由 nginx 限速；令牌具有有效期、使用上限和撤销开关。
- **一致性**：领取名额检查、Edge 创建、领取记录创建和计数递增在同一数据库事务中完成。
- **兼容性**：旧 Edge API、旧安装参数和已注册 Edge 不变；新表采用 expand-only 迁移，可滚动升级。
- **运维 / 回滚**：回滚应用版本后新表保留但不会被旧版本读取；已领取的独立 Edge 凭证仍按旧链路工作。

## API 变更

在 `api/manager/edge/v1/edge.proto` 新增：

```text
POST /api/v1/edge-enrollment-profiles
GET  /api/v1/edge-enrollment-profiles
POST /api/v1/edge-enrollment-profiles/{id}/revoke
POST /internal/edge/enroll
```

前三个接口需要管理员 JWT。领取接口使用安装令牌作为 Bearer capability，不使用用户 JWT；成功响应仅一次返回新 Edge 的 AccessKey 和 SecretKey。

## 数据库变更

- 新增 `edge_enrollment_profiles`：保存安装配置、令牌摘要、模式、可选集群节点、有效期、使用上限、计数和撤销状态。
- 新增 `edge_enrollments`：保存配置与独立 Edge、主机指纹、设备和领取审计信息的关联。
- 不修改已有 `edges`、`devices`、`nodes` 和 `relations` 字段。

## 依赖与阻塞

- **依赖**：现有 Edge 身份签发、HostInfo 指纹、设备拓扑镜像和通用 Topology 关系能力。
- **阻塞**：无。

## 风险与假设

- **已知风险**：安装命令通常会进入 shell history；因此令牌必须短期、限次、可撤销，且不能等同于长期 Edge 凭证。
- **已知风险**：默认自签名部署仍可能需要 `curl -k` / `--tls-insecure`；正式环境应配置可信 HTTPS 证书后移除该选项。
- **假设**：一台主机在一个安装配置内只应创建一个 Edge 身份。
- **未知项 / TODO**：后续可增加来源 CIDR 白名单与令牌轮换，不作为首版阻塞项。
