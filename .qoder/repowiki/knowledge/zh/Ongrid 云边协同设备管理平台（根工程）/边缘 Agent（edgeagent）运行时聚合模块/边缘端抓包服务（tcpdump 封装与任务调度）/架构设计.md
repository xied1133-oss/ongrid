模块按平台构建标签拆分：`capture_linux.go` 实现真正的抓包逻辑，`capture_other.go` 在非 Linux 平台返回 `supported on linux only` 占位；`service_linux.go` 在此基础上提供异步任务服务。
- 核心抽象：`Request`/`Result`/`ProgressReporter` 定义请求与结果结构，`Capturer` 封装单次抓取，`Service` 管理多个 `Task` 的生命周期。
- 抓取流程（Linux）：`Capture` → `captureInNamespace`（通过 `unix.Setns` + `runtime.LockOSThread` 进入指定 network namespace）→ `captureCurrentNamespace`，后者启动两个 `tcpdump` 子进程——一个以 `-w -` 写 PCAP，另一个以 `-l -n -q -r -` 实时解码输出文本行作为 `LivePreview`；两者通过管道合并写入文件并统计字节数。
- 资源限制：通过 `normalizeRequest` 对 capture_id、interface、network_namespace、filter、duration、max_bytes、max_packets、snaplen 做白名单校验与默认值填充，防止任意 BPF 表达式注入。
- 任务调度（Service）：维护 `tasks map[string]*taskState`，最多允许 `maxQueuedCaptures=10` 个并发任务；`Start` 先归一化参数再入队，后台 goroutine 轮询 `canRunLocked` 保证同一时刻仅一个运行中的任务，避免 AF_PACKET 重复采集导致内存/磁盘压力翻倍；支持 `Cancel`（立即中断）、`Stop`（优雅中断并保留有效 PCAP 前缀）、`Read`（读取最终 PCAP 并计算 SHA256）。
- 依赖方向：`service_linux.go` 依赖 `capture_linux.go` 暴露的 `Capturer` 与 `ProgressReporter`；非 Linux 平台通过 `capture_other.go` 提供同名类型与空实现，使上层无需感知平台差异。
