- 每个处理器遵循统一模式：`makeXxxHandler(sb, log)` 返回 `tunnel.Handler`，内部先 JSON 反序列化请求、校验 paths 数量上限 `hostFilesMaxPaths`，再调用共享的 `runBatch` 并发处理各 path。
- 所有外部 IO（find/du/df 子进程、os.Stat）在执行前必须经过 `sb.ValidatePath(path)` 校验，并在每 path 上应用 `hostFilesPerPathTimeout` 上下文超时。
- OS 差异通过带 `//go:build linux` / `//go:build darwin` / `//go:build windows` 标签的同名函数文件拆分（如 `fileTimes`、`fileOwner`），主逻辑文件仅声明接口调用而不感知平台细节。
- handler 日志统一使用 `log/slog`，且允许传入 nil logger 时回退到 `slog.Default()`，便于测试注入或生产配置。
- 批处理结果保持输入顺序：预分配等长切片后按索引写入，`runBatch` 保证 goroutine 间无锁并发，单个 path 错误以 `ResultEntry.Error` 字段上报而不中止批次。
