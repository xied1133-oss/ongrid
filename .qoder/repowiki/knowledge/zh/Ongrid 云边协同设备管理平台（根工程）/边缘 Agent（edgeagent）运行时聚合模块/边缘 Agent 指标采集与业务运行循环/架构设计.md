模块由两个子包构成清晰的分层：
- `internal/edgeagent/collector` 提供可插拔的指标源抽象 `Collector` 接口（定义于 `types.go`），包含两种实现：`embedded.go` 通过 gopsutil v3 无 CGO 读取本机 CPU/内存/负载/网络/磁盘并输出 node_exporter 兼容名称；`scrape.go` 按 `scrape_config.example.yaml` 配置并发拉取多个目标的 `/metrics`，经 `expfmt` 解析后存入 per-target snapshot，并通过 `mapper.go` 映射为 `tunnel.PromSample`。`composite.go` 中的 `CompositeCollector` 将二者组合，优先使用 host-role 的 scrape 结果覆盖 fast path，否则回退到 embedded。
- `internal/edgeagent/biz` 是业务运行循环所在（`doc.go` 明确职责）。`agent.go` 中的 `Agent` 持有 `tunnel.Client`，在 `Run()` 中注册云→边 RPC 处理器（心跳、`get_host_load`、`get_process_list`、抓包、技能调度、远程升级），启动 errgroup 管理 heartbeatLoop、metricsLoop、可选 networkDiscoveryLoop，并通过 `upgradeRequested` channel 触发优雅退出让 systemd 执行二进制替换。`snmp_probe.go` 用 gosnmp 对远端设备做只读 SNMP 探测；`packet_capture.go` 封装 packetcapture.Service 暴露抓包能力；`upgrade.go`/`upgrade_package.go` 处理 fetch/apply package 流程。
依赖方向单向：biz → collector 接口 + tunnel 协议类型；collector 不依赖 biz。两者都通过 `tunnel` 包与云端通信，避免反向耦合。
