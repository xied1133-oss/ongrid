- 每个业务域通过 `data/store.Migrate` 函数集中声明数据库表结构，由入口在启动时按固定顺序批量调用，新增领域需在此处追加迁移函数。
- 服务间依赖通过 Usecase 的 `SetXxx` setter 注入（如 `SetTopologyMirror`、`SetRemoteWriteResolver`、`SetAuthz`），而非构造函数参数，便于测试替换与延迟绑定。
- 对外部依赖（Grafana/Loki/Tempo/LLM Provider）采用 Resolver 模式配合 system_settings 缓存，管理员 UI 修改在约 60s 内生效而无需重启进程。
- 首次启动时的种子数据统一通过 `settingSvc.SetIfAbsent` 写入，保留管理员后续编辑结果，避免被重启覆盖。
- HTTP handler 构造后统一调用 `SetAuthz(authzMW)` 挂载 casbin 中间件，确保 mutating 路由受 RBAC 保护。
- 异步或可能阻塞的后端初始化（如 Grafana SA bootstrap、monitor dashboard sync）放入 goroutine 并以 rootCtx 控制生命周期，不阻塞主 API 启动。
