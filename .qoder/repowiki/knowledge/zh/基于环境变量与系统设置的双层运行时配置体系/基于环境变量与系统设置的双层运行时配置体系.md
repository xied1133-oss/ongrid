## 1. 采用的方案

Ongrid 采用**纯环境变量 + 数据库持久化系统设置**的双层配置模型，不依赖任何第三方配置库（如 viper、godotenv）。核心入口 `internal/pkg/config` 通过 `os.Getenv` 直接读取以 `ONGRID_` 为前缀的环境变量，并附带 Go 代码中内置的默认值；启动时再将这些 env 值“播种”到数据库的 `system_settings` 表中，供管理员在 Web UI 中后续修改。

- **进程级配置**：`internal/pkg/config/config.go` 中的 `Config` 结构体集中声明所有运行时参数，由 `Load()` 函数统一解析。支持 string / int / float64 / time.Duration / []string / bool 等类型，并提供 `getEnvBool`、`getEnvCSV`、`getOptionalURL`、`getEnvDuration` 等辅助解析器。
- **持久化/可热更新配置**：`cmd/ongrid/main.go` 在迁移完成后调用 `settingSvc.SetIfAbsent(...)` 将 env 值写入 `system_settings`（按 category 分组：LLM、Prom、Grafana、Loki、Tempo、WebSearch 等），并通过 Resolver（带 ~60s TTL 缓存）让管理员在 UI 中的修改在不重启的情况下生效。
- **边缘侧额外文件配置**：当 `CollectorMode == "scrape"` 时，edge 还会从 `ScrapeConfigFile`（默认 `/etc/ongrid-edge/scrape.yaml`）加载多目标 scrape 配置，格式见 `internal/edgeagent/collector/scrape_config.example.yaml`。

## 3. 架构与设计约定

### 3.1 环境变量命名规范
所有运行时配置均使用 `ONGRID_` 前缀（例如 `ONGRID_DB_DSN`、`ONGRID_PROM_URL`、`ONGRID_ALERT_CPU_PERCENT`），便于在 shell/compose/systemd 环境中批量识别和注入。部分非 `ONGRID_` 前缀的变量用于特定场景（如 `OPENAI_API_KEY`、`MYSQL_PASSWORD`、`GRAFANA_ADMIN_PASSWORD`），通常由 `install.sh` 生成或透传给下游容器。

### 3.2 分层加载顺序
1. **Go 内置默认值**：`Load()` 中每个字段都有硬编码 default（如 HTTP 端口 `:8080`、DB DSN 指向本地 MySQL、Logs URL 指向 `http://loki:3100`）。
2. **环境变量覆盖**：若对应 `ONGRID_*` 变量存在且非空则覆盖默认值。
3. **首次启动播种**：`main.go` 调用 `SetIfAbsent` 将 env 值写入 `system_settings` 表——仅当该行不存在时才写入，因此管理员在 UI 中的修改会永久保留。
4. **运行时 Resolver**：LLM、Prom、Loki、Tempo 等组件通过 Resolver 读取 `system_settings`，TTL 约 60 秒，无需重启即可热生效。

### 3.3 配置项分组
`Config` 结构体按功能域划分子结构体，每个子结构体对应一组相关环境变量：
- `DBConfig`：`ONGRID_DB_DIALECT` / `_DSN` / `_PATH`
- `JWTConfig`：`ONGRID_JWT_SECRET` / `_ACCESS_TTL` / `_REFRESH_TTL`
- `OpenAIConfig` / `LLMConfig`：各 LLM 提供商的 API Key、Model、BaseURL、Models 列表
- `AdminConfig`：`ONGRID_ADMIN_EMAIL` / `_PASSWORD`
- `EdgeConfig`：`ONGRID_EDGE_CLOUD_ADDR` / `_ACCESS_KEY` / `_SECRET_KEY` / `_COLLECTOR_MODE` / `_SCRAPE_CONFIG_FILE` / `_COLLECTOR_INTERVAL`
- `FrontierClientConfig`：`ONGRID_FRONTIER_ADDR` / `_SERVICE_NAME` / `_DISABLED`
- `PromConfig`：`ONGRID_PROM_ENABLED` / `_URL` / `_REMOTE_WRITE_URL` / `_QUERY_URL` / TLS 选项
- `GrafanaConfig`：`ONGRID_GRAFANA_INTERNAL_URL` / `_BOOTSTRAP_USER` / `_BOOTSTRAP_PASSWORD` / `_TLS_INSECURE`
- `NotificationConfig`：全局开关 + Webhook/Slack/Feishu/DingTalk 各通道
- `AlertConfig`：主机告警阈值、冷却时间、评估间隔
- `LogsConfig` / `TracesConfig`：Loki/Tempo 查询 URL
- `PacketCaptureConfig`：私有 PCAP 解析器集成
- `SkillsConfig`：外部 skill 目录白名单

### 3.4 特殊语义
- `getOptionalURL`：当值为 `off`/`disabled`/`disable`/`none`/`null` 时返回空字符串，用于显式禁用某能力（如 Loki/Tempo 查询）。
- `splitProviderModels`：逗号/分号分隔的模型列表去重后传入，空输入返回 nil，由上层决定是否回退到默认模型。
- `getEnvDuration`：除标准 `time.ParseDuration` 外，还接受纯整数秒作为便捷写法。
- JWT Secret 安全校验：`main.go` 启动时检测到仍为内置默认值 `dev-insecure-secret-change-me` 则直接 `os.Exit(1)`，强制更换。

## 4. 约定与约束

- **单一配置源**：所有 `Config` 字段必须通过 `internal/pkg/config.Load()` 读取，禁止在业务代码中直接 `os.Getenv`（除少数临时用途如 `ONGRID_OTEL_ENDPOINT`、`ONGRID_AUDIT_RETENTION_DAYS`、`ONGRID_EDGE_BUNDLE_DIR` 等仍在 main 中直读）。
- **环境变量前缀**：新增配置项应使用 `ONGRID_` 前缀，并在 `config.go` 的 `Load()` 中添加解析逻辑，同时在 `config_test.go` 中补充默认值与覆盖测试。
- **默认值策略**：所有字段必须有合理默认值，使单容器/开发环境开箱即用；敏感字段（如密码、密钥）默认应为空，由安装脚本生成或要求 operator 显式设置。
- **可空/禁用模式**：对外部依赖（Loki、Tempo、Prometheus、Grafana、PCAP Parser）采用“默认启用但可空”的模式——URL 为空即表示该能力不可用，API 返回 503 而非报错退出。
- **配置与密钥分离**：连接地址等非敏感配置可通过 env 播种到 `system_settings` 并由 UI 编辑；API Key、Secret 等敏感信息优先走 env，UI 中通过加密 vault 管理。
- **边缘 scrape 配置独立文件**：`scrape.yaml` 是可选的外部 YAML 文件，仅在 `CollectorMode=scrape` 时加载，失败不会阻止 edge 启动（降级为 embedded 模式）。
- **compose 与环境文件**：`deploy/docker-compose.yml` 负责将宿主机 `.env` 中的变量映射为容器内的 `ONGRID_*` 环境变量；`deploy/install/edge/ongrid-edge.env.example` 是 systemd 服务的 EnvironmentFile 模板，由 `install-edge.sh` 渲染后写入 `/etc/ongrid-edge/ongrid-edge.env`。
- **向后兼容**：旧版 `OPENAI_*`、`LOG_QUERY_URL` 等变量名仍被保留，新变量（如 `ONGRID_OPENAI_*`、`ONGRID_LOG_QUERY_URL`）逐步替代。
