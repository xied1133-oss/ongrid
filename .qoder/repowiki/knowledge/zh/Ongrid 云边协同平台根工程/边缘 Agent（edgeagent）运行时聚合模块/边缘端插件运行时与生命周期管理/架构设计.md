模块以 `plugin.go` 中定义的 `Plugin` 接口为核心契约（Name/Configure/Start/Stop/HealthSnapshot），由 `Supervisor` 在独立 goroutine 中按 60s 周期轮询 `ConfigFetcher.Fetch()` 返回的期望配置，对已注册的插件做 diff 并执行启停、重载；`SubprocessPlugin`（subprocess.go）封装了 otelcol-contrib 等外部二进制的全生命周期：渲染配置到工作目录、原子 stage-validate-replace、SIGTERM 优雅退出、崩溃指数退避重启（1s→5min cap）、健康状态与 PID 追踪。两种配置来源通过 `ConfigFetcher` 抽象解耦：`EnvConfigFetcher` 从 `ONGRID_EDGE_PLUGIN_*` 环境变量读取（开发/冷启动兜底），`TunnelConfigFetcher` 通过 `tunnel.Client.Call(MethodGetPluginConfigs)` 从 Manager 拉取并按 K8s 角色注入默认值（logs/traces/metrics/hostmetrics/procmetrics 各有专用 `withKubernetes*Defaults`）。内置 in-process 插件（如 `metrics`）直接实现 `Plugin` 并通过 tunnel RPC 推送采样；子进程型插件（`logs`、`traces`、`hostmetrics`、`procmetrics`、`custommetrics`、`databasemetrics`）仅负责渲染各自 spec 为配置文件或 CLI 参数，复用同一 `SubprocessPlugin` 骨架。可选扩展点 `ReadyPlugin.WaitReady` 用于等待异步就绪，`ConfigApplyReporter.ReportPluginConfigApplied` 用于向 Manager 回写配置生效状态。
