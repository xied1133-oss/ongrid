模块按职责拆分为四个文件，形成「解析 → 策略判定 → 沙箱执行」的单向依赖链：
- `types.go` 定义核心类型（`BinaryClass`、`ArgMatcher`、`BinaryPolicy`、`Policy`、`Decision`），确立五类二进制分类（read-fs / read-system / mixed / network / denied）及匹配器模型。
- `parse.go` 实现手写 POSIX 子集 tokenizer，仅允许单引号/双引号、转义与 `|` 管道，拒绝重定向、命令替换、后台等危险语法，产出分段 argv 供上层使用。
- `policy.go` 维护默认只读基线（`DefaultReadOnly()`，覆盖 ps、df、iptables -L、ip netns list、bpftool 等 ~60 个诊断工具），并通过 `LoadFromYAML` 以「追加 + 覆盖」语义合并 `/etc/ongrid-edge/bash-policy.yaml`；`Decide` 逐段执行 DeniedArgs 子串黑名单、`ReadOnlyMatchers`/`WriteMatchers` 匹配与 class 默认决策。
- `sandbox.go` 在策略之上叠加路径校验（通过 `PathValidator` 接口复用 host_files）、网络目标主机白名单（CIDR/后缀/精确匹配）、`exec.Command` 管道编排、上下文超时与 stdout/stderr 截断；并提供 `ExecRaw` 作为管理员写门控逃逸通道（绕过所有策略检查，但仍受超时与输出上限约束）。
依赖方向严格自下而上：sandbox 依赖 policy，policy 依赖 parse/types，对外仅暴露 `Policy`、`Sandbox`、`PathValidator` 三个边界点。
