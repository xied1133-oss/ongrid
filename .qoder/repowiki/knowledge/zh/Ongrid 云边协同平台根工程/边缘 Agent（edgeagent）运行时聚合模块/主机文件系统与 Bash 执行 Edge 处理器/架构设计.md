模块由两个并列子包组成：`host_files` 实现三个基于路径的只读文件查询处理器（find/du/stat），`bash` 实现一个通用 shell 执行处理器。两者都通过 `internal/pkg/tunnel.Client.RegisterHandler` 注册到隧道层，由 manager 侧 BaseTool 经 frontier tunnel 调用。

- 入口：`handlers.go` 中的 `Register(client, log)` 负责构造 `SandboxConfig`、校验依赖二进制并安装 handler；`bash/handlers.go` 的 `Register` 额外加载 `/etc/ongrid-edge/bash-policy.yaml` 覆盖默认只读策略。
- 沙箱隔离：`sandbox.go` 定义 `SandboxConfig`，采用「denylist + 可选 allowlist」双阶段路径校验（`ValidatePath`），并通过 `AllowedBinaries` 白名单控制可执行的 `find`/`du`/`df`/`stat`/`ls` 二进制。
- 并发模型：所有处理器共享 `runBatch[T]` 泛型原语，使用 `golang.org/x/sync/errgroup` 以 `hostFilesBatchConcurrency=4` 限制并发，每个 path 独立超时 `hostFilesPerPathTimeout=30s`，整批超时 `hostFilesBatchTimeout=60s`；单 path 错误写入结果项 `.Error` 而非中断批次。
- OS 差异通过 Go build tag 拆分：`owner_unix.go`/`owner_windows.go` 处理 owner/group 解析，`times_linux.go`/`times_darwin.go`/`times_windows.go` 处理 atime/mtime 读取，`handlers.go` 中 `runFindLargeFiles`/`runDu`/`runDfOne` 用 `runtime.GOOS` switch 选择不同命令行参数（GNU find `-printf` vs BSD `stat -f`，`du -B1` vs `-k`）。
- 依赖方向：`bash` 包复用 `host_files.DefaultSandboxConfig()` 作为 `cmdpolicy.Sandbox.PathValidator`，使 bash 技能与文件工具共享同一份路径白名单；两者均仅依赖 `internal/pkg/tunnel` 的协议类型，不反向依赖上层 manager。
