模块采用经典的四层分层：`server/*` 通过 go-chi/v5 暴露 REST 路由，仅依赖 `service/*` 的接口；`service/*` 是应用服务层，负责参数校验、DTO 转换和调用 `biz/*` 用例；`biz/*` 实现领域用例（如 alert pipeline、aiops agent 循环、flow engine、imbridge stream supervisor），并通过 `data/*/store` 中的 GORM Repo 访问 SQLite/ClickHouse；`model/*` 定义跨层共享的存储模型。每个子域（alert、aiops、device、edge、knowledge、report、metric、imbridge、topology、secret、setting、marketplace、mcp、packetcapture、promwrite、monitor、operatorrun、webshell、approval、audit、flow、grafana、k8s、logs）都遵循相同的 biz/service/server/store 目录镜像结构，依赖方向严格自上而下（server→service→biz→data）。AIOPS 子域内部进一步拆分为 agent/chatruntime/graph/tools/basetool/decorators 等子包，工具通过 `tools/registry.go` 注册并以装饰器链（审计、限流、超时、人工审批、租户绑定）组合。HTTP 层通过 chi.Router.Register 集中挂载路由，鉴权从 `internal/pkg/tenantctx` 提取 Caller，审计事件经 `server/middleware` 注入到 biz/audit。数据层每个 store 包包含 migrate.go + repo.go，统一使用 gorm.DB 并返回统一的 `internal/pkg/errs` 错误类型。
