模块按部署目标划分为三个层次：
- `deploy/`：容器化与本地开发栈。顶层 `docker-compose.yml` 编排 MySQL + ongrid + frontier + nginx + prometheus + grafana；各 `Dockerfile.*` 分别构建云端（cgo + ONNX Runtime）、Edge（纯 Go distroless）和 Web 镜像；`install/` 是随 tar.xz 发布包提供的生产安装脚本集（`install.sh` / `upgrade.sh` / `uninstall.sh`），通过渲染 `.env`、生成自签证书、拉取精确镜像并 `docker compose up -d` 完成单主机部署，Edge 侧通过 `edge/install-edge.sh` 以 systemd 服务运行。
- `deploy/kubernetes/ongrid/`：Helm Chart，使用 `templates/` 下的 Deployment、DaemonSet、RBAC、ConfigMap、Secret 等模板配合 `values.yaml` 在 K8s 上部署 manager、edge 节点、telemetry-gateway 与 kube-state-metrics。
- `db/migrations/`：按 `YYYYMMDDHHMMSS_<desc>.up.sql` / `.down.sql` 命名存放 golang-migrate 迁移文件，生产环境通过 `make migrate-up/down` 显式执行，本地与全新安装则依赖 GORM AutoMigrate 自动初始化空库。
依赖方向单向：应用代码消费这些静态资产进行部署，部署脚本不反向引用业务代码，仅通过环境变量与配置文件驱动运行时行为。
