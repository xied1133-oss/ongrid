单包 `main` 作为 Go 二进制入口，按命令行子命令分流：`enroll`（enroll.go）通过 Manager `/internal/edge/enroll` 获取 edge_id/access_key/secret_key 并原子写入环境变量文件；`prepare-k8s-upgrade`（k8s_upgrade.go）委托 internal/edgeagent/k8s 完成 Deployment 滚动准备；`install-k8s-host-runtime` / `enter-k8s-host`（k8s_host_runtime.go + k8s_host_runtime_linux.go）在宿主机上复制二进制、插件和 serviceaccount 到 `/var/lib/ongrid-edge/k8s-runtime`；当 `ONGRID_EDGE_MODE=k8s-telemetry-gateway|k8s-metrics-scraper` 时进入独立数据面模式（k8s_data_plane.go），仅暴露 `/metrics`、`/healthz`、`/readyz` 诊断端口并通过 Secret 文件驱动遥测网关或 remote_write 抓取器。

默认主流程（main.go）加载配置后建立 tunnel 客户端，根据 `CollectorMode`（off/auto/embedded/scrape）构建采集器，注册 host_files/restart_service/bash/operator/webshell/streamrouter 等能力，并在 controller/node 角色下分别启用 inventory/metrics pusher 或禁用 host 能力；插件子系统通过 edgeplugins.Supervisor 管理日志/追踪/指标/数据库导出器等子进程，健康快照经 `SetPluginHealthFn` 上报给 manager。

K8s 凭证体系集中在 k8s_credentials.go：优先从 `ONGRID_K8S_CREDENTIAL_FILE` 读取本地 JSON，否则通过 ServiceAccount token 访问 Kubernetes API 的 Secret（`/api/v1/namespaces/{ns}/secrets/{name}`）以 base64 data key 形式存取 edge 凭据与 telemetry 配置；controller 额外维护独立的 telemetry Secret，支持 per-signal auth mode（telemetry/backend）及 TLS 同域跳过校验。

依赖方向单向向外：本模块仅消费 `internal/pkg/*`、`internal/edgeagent/*`、`internal/skill/builtin` 等内部包，不反向被它们引用，保证二进制入口的纯粹性。
