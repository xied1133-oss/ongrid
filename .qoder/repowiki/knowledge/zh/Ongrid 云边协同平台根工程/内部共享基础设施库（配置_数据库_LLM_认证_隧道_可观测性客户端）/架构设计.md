本模块按能力划分为多个独立子包，每个子包对外暴露最小接口，供上层业务组合使用，依赖方向自顶向下：业务调用 → 具体能力包（llm/tunnel/logquery/prom*）→ 基础包（config/dbx/auth/tenantctx），包之间不反向依赖业务域。
- 配置层 `config`：通过 `os.Getenv` + 默认值集中加载所有运行时参数（HTTP/Metrics/Tunnel 地址、DB、JWT、OpenAI/多 LLM 提供商、Prometheus/Grafana/通知/告警/日志/追踪/抓包/Skills 等），是其他包的唯一配置来源，提供 `Load()` 入口。
- 数据访问层 `dbx`：基于 GORM 封装 MySQL/SQLite 双后端，统一 `Open` 入口，SQLite 启用 WAL/busy_timeout/foreign_keys 等 pragmas，MySQL 启动时 Ping 验证连通性；`migrate.go`、`soft_delete.go` 提供迁移与软删除扩展。
- LLM 抽象层 `llm`：定义 `Client` 接口与 OpenAI-flavored 的 `Message`/`ToolCall`/`ChatReq` 数据结构，内部以 `openaiClient` 实现并缓存 SDK 实例（按 apiKey+baseURL 键），支持 `Resolver` 动态注入凭据、`BudgetChecker` 令牌预算、`TimeoutProvider` 超时控制、Zhipu JWT Transport 自动签名以及针对推理模型的采样参数自适应重试；`router.go`/`eino_routing.go` 负责多 Provider 路由。
- 认证鉴权 `auth` + `authzmw`：`jwt.go` 提供 JWT 签发/校验，`middleware.go` 作为 HTTP 中间件解析 Bearer/token query，将 `tenantctx.Tenant` 写入请求上下文；`authzmw` 提供基于角色的授权中间件。
- 隧道通信 `tunnel`：基于 `github.com/singchia/geminio` 封装 Edge→Cloud 的长连接 RPC，内置指数退避重连、TLS CA 校验、连接代际管理、断线回调与流式通道；各文件按职责拆分（消息类型、主机文件、包捕获、重启服务等）。
- 可观测性与外部服务：`prom`/`promauth`/`promquery`/`promwrite` 封装 Prometheus 指标采集、认证、查询与远程写入；`logquery` 统一 Loki/Elasticsearch 日志查询；`tracequery` 对接 Tempo；`grafana`、`qdrantx`、`mcpclient`、`zhipuauth` 分别对接 Grafana、Qdrant、MCP 客户端与智谱鉴权。
- 辅助工具：`logger`、`tracing`、`secretbox`、`passwd`（argon2）、`k8sredact`、`credinject`、`runner`、`workspace`、`notify`、`embedding`、`docextract`、`httpserver`、`errs`、`tenantctx` 等。
